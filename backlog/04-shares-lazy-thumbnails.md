# 04. Ленивые превью (миниатюры) в модуле Shares

**Status:** Done  
**Приоритет:** Средний  
**Платформы:** Windows, Linux, Android

## Контекст
В оригинальной Landa миниатюры генерировались заранее при `re-cache` и пересылались по UDP, что создавало большую нагрузку на CPU, диск и сеть. В Landa 2 превью должны работать **строго лениво по запросу** только для видимых в списке файлов.

## Что нужно сделать
1. **Протокол `landa-mod-shares`**:
   - Добавить запрос `ShareRequest::GetThumbnail { root_id, rel_path, max_size }` поверх существующего шифрованного QUIC-потока.
   - На стороне владельца папки: генерировать компактный WebP/JPEG-превью (например, 160×160) только для изображений (через лёгкий крейт `image` с отключёнными лишними форматами) и кэшировать в памяти/диске с жёстким лимитом размера (например, LRU 50 МБ).
2. **UI (`SharesView.tsx`)**:
   - Переключатель вида «Список / Плитка».
   - Ленивая подгрузка миниатюр через `IntersectionObserver` только для видимых карточек.
